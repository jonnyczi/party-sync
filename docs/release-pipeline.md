# Release pipeline

Reproducible, CI-portable Android release builds for **GitHub Releases** (now),
**F-Droid** (next), and **Google Play** (later). Designed so the same build runs
locally and on any CI with only a container runtime.

## Architecture / division of labour

- **`flake.nix`** — single source of truth for the toolchain (JDK 17, Android
  SDK/NDK, gradle, node, curl, git). Used directly for **interactive dev**
  (`expo run:android`, hot reload on a device/emulator).
- **Dagger module (`.dagger/`, `dagger.json`)** — produces the **release
  artifacts** (APK/AAB). It runs the build inside a `nixos/nix` container via
  `nix develop`, so the flake stays the only toolchain definition and the only
  local prerequisite is Docker/Podman — no Nix, no Android SDK on the machine.
- **`scripts/ci-android-build.sh`** — the actual build steps (npm ci → `expo
  prebuild` → gradle), shared by local and Dagger builds. It also re-hardens the
  gradle wrapper `networkTimeout` *after* prebuild (the flake shellHook can't —
  `android/` doesn't exist when the shell loads).
- **`.github/workflows/`** — thin wrappers that install the Dagger CLI and run
  `dagger call …`. Porting to another CI = run the same `dagger call`.

## Local builds (only Docker required)

```sh
dagger call lint                                   # expo lint (node container)
dagger call test                                   # vitest (node container)
dagger call build-apk export --path ./out/app.apk  # debug-signed release APK
dagger call build-aab export --path ./out/app.aab  # release AAB (Play)
```

Signed build (uses the upload keystore; otherwise falls back to debug signing):

```sh
dagger call build-apk \
  --keystore=file:upload.keystore \
  --keystore-password=env:STORE_PW \
  --key-alias=env:KEY_ALIAS \
  --key-password=env:KEY_PW \
  export --path ./out/app.apk
```

To build with the flake directly instead of Dagger (e.g. on this dev machine):
`nix develop --command ./scripts/ci-android-build.sh apk`.

## Signing

`android/` is regenerated by `expo prebuild` every build, so the release
signing config is injected by the Expo config plugin
**`plugins/withReleaseSigning.js`**, which reads these env vars at Gradle eval
time (falling back to debug signing when absent — this keeps dev builds and
F-Droid's from-source build working):

| Env var | Meaning |
| --- | --- |
| `COPYPARTY_UPLOAD_STORE_FILE` | path to the `.keystore` |
| `COPYPARTY_UPLOAD_STORE_PASSWORD` | keystore password |
| `COPYPARTY_UPLOAD_KEY_ALIAS` | key alias |
| `COPYPARTY_UPLOAD_KEY_PASSWORD` | key password |

Generate the upload keystore once (kept out of git; `*.keystore` is gitignored):

```sh
keytool -genkeypair -v -keystore upload.keystore -alias upload \
  -keyalg RSA -keysize 2048 -validity 10000
```

This is the **upload** key. On Google Play, Play App Signing manages the real
app-signing key. **F-Droid signs with its own key**, so a package installed from
F-Droid is not cross-updatable with the Play/GitHub build (a known, accepted
caveat).

CI secrets used by `release.yml`: `UPLOAD_KEYSTORE_BASE64` (base64 of the
keystore), `UPLOAD_STORE_PASSWORD`, `UPLOAD_KEY_ALIAS`, `UPLOAD_KEY_PASSWORD`.

## Versioning

`app.json` is the single source of truth: `expo.version` → `versionName`,
`expo.android.versionCode` → `versionCode` (also what F-Droid reads). Bump both
(and keep `package.json` in sync) with:

```sh
npm run bump-version patch        # or minor | major | X.Y.Z
git commit -am "release vX.Y.Z" && git tag vX.Y.Z && git push --tags
```

`release.yml` asserts the tag matches `app.json` (`bump-version.mjs --check`).

## Per-store

- **GitHub Releases** — `.github/workflows/release.yml` on tag `v*`: build signed
  APK + AAB, publish a Release with both + `SHA256SUMS`.
- **F-Droid** — _(pending)_ F-Droid builds from source on its own infra from a
  metadata recipe (`metadata/io.github.jonnyczi.copypartyclient.yml`). Enabled
  by the de-Googling below.
- **Google Play** — _(pending)_ upload the AAB to the `internal` track via a
  service account.

## De-Googled notifications (F-Droid prerequisite)

`expo-notifications` pulls in Firebase Cloud Messaging on Android (an F-Droid
blocker) even though the app only posts a local foreground-sync notification. It
was replaced by **`modules/copyparty-notify`** (a pure-Kotlin Expo module using
only `androidx.core`) plus RN's built-in `PermissionsAndroid` for the
POST_NOTIFICATIONS prompt. Result: **zero** `com.google.firebase`/`gms` classes
in the release APK.

## Known issues / follow-ups

- **Cleartext HTTP is blocked in release builds** — plain `http://` copyparty
  servers fail at runtime with "Network request failed" (works in dev). Needs a
  network-security-config decision via `app.json`/config plugin. Not yet fixed.
- **Cold Nix builds in CI** — GitHub-hosted runners have no persistent `/nix`,
  so `build-apk` rebuilds the toolchain each run (slow). Mitigate with Dagger
  Cloud caching or a self-hosted runner.
