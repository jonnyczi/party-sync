# Implementation plans

Five feature plans, each implemented by its **own Claude Code session**, on its
**own branch**, shipped as its **own PR**. Each file is self-contained — it
restates the shared constraints and the decisions already locked with the user,
so a fresh session needs no other context.

## Order (strict)

| # | Plan | Branch | Depends on |
|---|------|--------|------------|
| 1 | [Engine throughput & richer progress](./01-engine-throughput-progress.md) | `feat/engine-throughput-progress` | — (foundation) |
| 2 | [Run control: cancel + retry-failed](./02-run-control-cancel-retry.md) | `feat/run-control-cancel-retry` | Plan 1 |
| 3 | [Completion & failure notifications](./03-result-notifications.md) | `feat/result-notifications` | Plan 1 (and Plan 2 if present) |
| 4 | [Camera-roll album filtering](./04-camera-roll-album-filter.md) | `feat/album-filter` | independent |
| 5 | [Android share target](./05-android-share-target.md) | `feat/share-target` | independent |

**Hard dependencies:** 1 → 2 and 1 → 3 (Plan 1 rewrites the upload loop and the
progress model that 2 and 3 build on). Plans 4 and 5 are independent of the
others but are sequenced last so their branches don't collide with the engine
work in 1–3. Do not start 2 or 3 until 1 is merged.

## Standing instruction for every session

Each plan ends with an **"Open questions for this session"** list. Before writing
any code, ask the user those questions (and any others you surface) and provide
suggestions until you are fully confident in the approach. Implement on the
plan's branch and open a PR.

## Shared constraints (apply to all plans)

- **Android-first.** The native modules (`modules/copyparty-sha512`,
  `modules/copyparty-notify`) are Android-only; iOS is out of scope.
- **Never hand-edit `android/`** — it's gitignored and regenerated by
  `expo prebuild`. All native config flows through `app.json` + Expo config
  plugins (`plugins/`).
- **De-Googled.** No Firebase / GMS. The `scripts/scan-nonfree-apk.py` CI gate
  fails the build if any `com.google.firebase`/`gms` class reappears. Keep using
  `modules/copyparty-notify` for notifications — **never** `expo-notifications`
  (it pulls in FCM).
- **Verify in the Android emulator** (not just unit tests) before committing.
  See `CLAUDE.md` → "Controlling the running emulator" and "Testing against a
  copyparty server" (dockerized copyparty at `http://10.0.2.2:3923` from the
  emulator, account `test` / `testpw`).
- **Version bumps** go through `npm run bump-version` (single source: `app.json`).
- Run `npm run lint` and `npm test` before opening a PR.

## Decisions already locked with the user

- Upload concurrency is a **per-job** setting (new `jobs` column).
- Total-run progress uses an **exact pre-scan pass**.
- Run control is **cancel-only** — pause/resume is out of scope.
- Retry-failed lives on the **run-detail screen** and retries **only that run's
  failed files**.
- Notifications fire on **all completions and all failures**, and are
  **tappable** (extend the native notify module).
- Album filtering is **single-album** (`album:<id>` sentinel).
- Share target = **server + folder picker → one-off upload** (SEND +
  SEND_MULTIPLE).
